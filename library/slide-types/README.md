# Archetyp-Katalog (Entwurf)

Designneutrale Baupläne für visuelle Folien. Jeder Archetyp definiert: **wann** er passt, **Kapazität** (max. Elemente / Wörter), **Varianten**.
Kapazitätswerte sind Platzhalter – werden anhand der Referenzfolien kalibriert.

| # | Archetyp | Trägt Aussagen wie … | Kapazität (vorläufig) | v1.0? |
|---|---|---|---|---|
| 1 | Kernaussage + 3 Treiber | „X gelingt nur, wenn A, B, C“ | 3–4 Säulen, je ≤ 25 Wörter | tbd |
| 2 | Roadmap / Gantt | „Umsetzung in 3 Wellen bis Q4“ | ≤ 6 Workstreams, ≤ 8 Meilensteine | tbd |
| 3 | Optionenvergleich | „Option B ist die beste Balance aus …“ | ≤ 4 Optionen × ≤ 5 Kriterien | tbd |
| 4 | 2×2-Matrix | „Fokus auf Quick Wins oben links“ | ≤ 10 Items | tbd |
| 5 | Prozesskette / Zielbild | „Zielprozess reduziert Schritte von 9 auf 5“ | ≤ 7 Schritte, je ≤ 8 Wörter | tbd |
| 6 | Status-/Risiko-Dashboard | „2 von 6 Workstreams gefährden Go-live“ | ≤ 8 Zeilen | tbd |
| 7 | Ist → Soll | „Von fragmentiert zu integriert“ | ≤ 5 Dimensionen | tbd |
| 8 | Wasserfall / KPI-Brücke | „Kosteneffekt von 12 Mio. durch …“ | ≤ 8 Balken | tbd |
| 9 | Organigramm / Governance | „Klare Entscheidungsrechte über 3 Ebenen“ | ≤ 3 Ebenen, ≤ 12 Boxen | tbd |
| 10 | Entscheidungsvorlage | „Vorstand beschließt heute Option B“ | Situation / Optionen / Empfehlung / Beschluss | tbd |

Pro Archetyp folgt später eine Datei `<archetyp>.yaml` mit Raster, Platzhaltern und Regeln.
